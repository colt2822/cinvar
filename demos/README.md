# CINVAR demonstrations - Operation First Light

All demos were run against the real binary with a real language model. Nothing here is the
offline mock planner.

| Demo | Who drives | Output |
|---|---|---|
| A - First Light | a real model over MCP | renders/first-light-trailer-v4.mp4 (regenerated by the script) |
| B - Director's Cut | the same model, follow-up instruction | renders/first-light-dramatic-open-v2.mp4 (regenerated by the script) |
| C - External Director | the same MCP session with no CINVAR-specific client code | covered by A and B |

## What 'real' means here

- Model: claude-sonnet-5-5 via the authenticated Claude Code CLI, talking to CINVAR's own
  MCP server over stdio with --strict-mcp-config (only the cinvar server is loaded).
- The model's only editing interface was the 52 CINVAR MCP tools. It could read the PNG
  frames CINVAR extracted. It had no shell access and no other MCP server.
- The prompts are exactly prompt.txt and revision_prompt.txt. No edit plan was provided.
- The raw model transcripts and rendered outputs were removed from the repository before
  publication (they embedded local paths and ~390 MB of generated media). Re-run
  `demos/run_first_light.sh` (needs the Claude Code CLI) to regenerate them. The numbers below
  are the recorded results of the original private run.

## What actually happened in Demo A

The model imported 7 assets, pulled contact sheets and scene lists, built a 7-clip 18 s
timeline, added a title, chose transitions, normalised quiet dialogue, rendered a preview,
extracted frames from that render, looked at them, found that its centred title collided
with the placeholder text baked into the clip, moved the title, re-rendered, and reported
what it fixed. Its closing report (in the original run's trace) lists the sequence, transitions,
audio gain, the fixes and the QA verdict.

## What actually happened in Demo B

The model reopened the same project, read the existing timeline, trimmed the opening from
4 s to 2 s, moved the later clips by hand because it did not know about ripple trimming
(defect 4), shortened the opening fade, added a zoom to the first and last shots, enlarged
and recoloured the title, re-rendered, inspected 10 frames, and reported exactly what
changed plus the rollback revision (31). It also reported two honest limitations: its title
scale-keyframes did not animate, and the audio track ends at 12 s of a 16 s runtime.

Rollback was verified independently: a copy of the project restored to revision 31 gives
back the 18 s / 7-clip timeline, and QA of the First Light render against that restored
project passes with score 1.000.

## Defects the live model surfaced, all fixed

1. Creative skills were invisible when the MCP host started the server outside the repo.
   The model called cinvar.skills.load and got an empty list. The shipped skills are now
   compiled into the binary; filesystem directories still override them by name.
2. wipeleft / wiperight / slideup / circleopen rendered as a dip to black. The model asked
   for transitions it never got. Those names are now rejected with the supported list
   (fade, fadeblack, fadewhite, crossfade, dissolve, none) instead of being substituted.
3. Renders could be written outside the project, which then blocked frame review. The
   cinvar.render.export tool now refuses paths outside the project root, with a hint.
4. Keyframes and trimming were misleading. Animated properties render at their first
   keyframe value and the render job now returns that warning; timeline.trim gained
   ripple: true so shortening a clip closes the gap instead of leaving a hole.

## Reproduce

    ./demos/run_first_light.sh      # regenerates footage and project if absent, runs Demo A
    ./demos/run_directors_cut.sh    # Demo B on the same project
    ./demos/verify_demos.sh         # ffprobe and CINVAR QA on every delivered render

Requirements: ffmpeg, cargo, and an authenticated claude CLI (or any MCP host; the script
writes a plain mcp.json). The model runs are not free: about $0.40 per demo with these
prompts.

## Limitations, stated plainly

- The footage is synthetic colour cards with white text, so 'choose the strongest shots' is
  a weak test of taste. The model said so itself rather than pretending otherwise.
- CINVAR's own agent loop (internal provider adapters, system prompt, skills) was not run
  against a vendor API: no API key exists on this machine and the DeepSeek platform token in
  the harness credential store is rejected by api.deepseek.com (401, verified). The
  corresponding report lines are BLOCKED, not PASS.
- In Demo B the model did not run cinvar.qa.render_check itself; it inspected frames and
  left final QA to verify_demos.sh, which passes.
